Foundations

Color, type, shape, motion, voice.

The settled vocabulary every component is built from. Everything here is Stable — these are ratified and the base the rest of the system stands on. Swatches render from the live --c-* tokens, so flip the theme to see both.

Color

Color is functional, never decorative (principle 2). Every component reads its color through a --c-* token; never a raw hex. The token resolves per theme automatically — both light and dark must read. There is no white token: text/icons on a colored fill use on-accent / on-cat.

Semantic tokens

The working palette. Use these for everything structural — surfaces, text, borders, and the four state hues. Light hex · dark hex shown under each.

The text ramp
Four weights of foreground, loudest to faintest: fg (primary) → dim (secondary) → muted (captions, sub-labels) → faint (timestamps, micro-eyebrows). Don't invent intermediate opacities — pick the rung that fits.

Category hues

Event-kind colors. Fixed mapping — a category always wears its hue. Dark uses lighter ramp stops, light uses deeper ones, for contrast on each bg.

Decorative ramps

The source ramps (50 lightest → 950 darkest) that the category + project tokens are drawn from. Use a ramp stop directly only for a chip/badge that needs a specific tint; otherwise reach for a semantic token.

Heads up — known debt

Three ramps are byte-identical duplicates of others (frozen-lake=sky-aqua, honey-bronze=amber-glow, grapefruit-pink=hot-fuchsia). Two new ramps — mulberry + terracotta — are in the palette but not yet mapped to a role (added alongside the chore→teal recolor, slice D). Prefer a named-and-mapped ramp; the duplicates should collapse.

Typography

Three roles, no fourth (principle 4). Sizes in the app are authored as fixed pixels and then scaled globally by body { zoom: 1.20 } (the comfortable/spacious density modes bump it to 1.35 / 1.50). The scale below shows the authored intent.

Lora — display & headings
Inter — uppercase eyebrows & labels
Nacelle — the body voice for everything else: prose, row text, values. It carries the bulk of the reading, so it stays quiet and even.
Nacelle is vendored in-app; these docs fall back to system-ui for body. Lora + Inter load from Google Fonts.

Two rules that carry the personality
Eyebrows are the app's signature label — Inter, uppercase, tracking-[0.12em] and up. They title sections and cards. Tabular numerals are mandatory for any data that lines up in a column — times, durations, counts — set with [font-variant-numeric:tabular-nums] and a fixed-width container so digits align.

Shape & space

Sharp corners

Cards, panes, rows, and inputs are square (principle 3). Rounding is reserved for genuinely circular things only:

Round these

Status / now dots, count badges, avatars, toggle knobs (rounded-full).

Never round these

Cards, panes, rows, inputs, sheets, buttons. A rounded card reads as a different product.

Density & spacing

No custom spacing or radius tokens — Tailwind defaults, applied with intent: generous padding inside panes, hairline gaps between rows. The deep place hierarchy uses --tree-indent: 18px / --tree-rail: 12px, tightened to 7px / 6px on phones.

Motion

Motion is sparse and fast. There are two animation tokens and one transition; we don't add ambient or decorative animation (it reads as generated, and it costs battery in the field).

TokenSpecUse
animate-flyout-in translateX(-8px)→0 + fade · 140ms ease Flyout panels, menus
animate-flyout-out reverse · 140ms ease forwards Flyout dismiss
theme swap background+color 120ms ease The body transition on theme change

Respect prefers-reduced-motion; the floor (visible focus, reduced motion) is non-negotiable.

Voice

Words are design material (principle 9). Copy is written from the operator's side of the screen, in the interface's voice.

Do
  • Active voice, plain verbs: "Save changes," not "Submit."
  • Sentence case everywhere except eyebrows (which are uppercase).
  • An action keeps its name through the flow — "Cover" → "Covered."
  • Name things by what the operator controls.
  • Empty states invite an action; errors say what to do next.
Don't
  • Marketing words: seamless, intuitive, clean, powerful.
  • System vocabulary in the UI: "webhook," "sync conflict," "null."
  • Vague errors or apologies. Say what happened.
  • Two elements doing the same job with different words.
